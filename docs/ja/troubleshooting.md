# トラブルシューティング

## 「Docker が必要です」/ Docker が実行されていない
Ensembler にはコンテナランタイムの実行が必要です。**Docker Desktop** を
お使いの場合は、起動して（インストールされているだけでなく）実行中と報告される
まで待つと、Ensembler が続行します。インストールされていない場合は、その画面の
ダウンロードリンクに従ってください。**OrbStack** や **Podman** のような代替を
お使いですか？それでも問題ありません。実行されていること、そして `docker` と
`docker compose` が動作することを確認してください。

## サービスが起動しない
- サービスの **⋯ メニュー → ログを表示** を開き、何が問題なのか確認します。
- **⋯ メニュー → 再起動** を試します。
- サービスの起動が完了する間、インポート通知やライブラリスキャンに1分ほど
  かかることがあるため、初回起動後は少し待ってください。

## Docker のメモリまたはディスク容量に関する警告
Docker に割り当てられたメモリが少ない、またはメディアディスクがほぼ満杯の場合、
Ensembler が警告します。これらはサービスが不調になる、目に見えにくい最も一般的な
2つの原因です。
- **メモリ:** コンテナランタイムの設定で増やしてください（Docker Desktop →
  Settings → Resources）。数個のサービスには 4 GB 以上が良い目安です。
- **ディスク:** ダウンロード/メディアが使用するドライブの空き容量を確保するか、
  サービスの **設定** 画面からより大きなドライブを指定してください。

## サービスを開くときの「Not Secure」警告
サービスは **Ensembler 内** でタブとして開くようになったため、通常これは
表示されません。サービスの **⋯ メニュー → ブラウザで開く** を使う（または
Ensembler を Web ブラウザで実行する）場合にのみ表示されます。ローカルサービスは
`http://localhost` 上で実行され、ブラウザはこれを「Not Secure」と表示します。
自分のマシン上のサービスにとってこれは想定内で無害です。データがコンピュータの
外に出ることはありません。

## ポートがすでに使用中
Ensembler はセットアップ時にポートをチェックし、デフォルトが使用中の場合は自動的に
空いているものを選ぶため、これはまれです。それでもサービスがバインドできない
場合は、別のアプリがそのポートを取得している可能性があります。そのアプリを
停止するか、サービスの **設定** 画面からポートを変更してください。

## データはどこにありますか？
- **アプリの設定** は、ユーザーごとの隠しフォルダにあります（*サービスの管理 →
  設定の保存場所* を参照）。編集する必要はありません。
- **メディア** は、セットアップ時に選んだ場所にとどまり、Ensembler によって
  移動されたり削除されたりすることはありません。

## ひどく動かなくなった — 最初からやり直す
**設定 → リセット → すべてリセット** で、すべてのサービスとその設定を停止・削除し、
Ensembler をクリーンな状態に戻します。**メディアファイルには影響しません** —
サービスとその設定のみが削除されます。その後、セットアップウィザードを
もう一度進めることになります。

## それでも解決しませんか？
サービスの **ログを表示** と **設定 → 詳細設定 → 診断** から詳細を取得して
ください。問題を報告する際に含めると最も役立つ情報です。
