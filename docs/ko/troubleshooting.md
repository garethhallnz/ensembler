# 문제 해결

## "Docker가 필요합니다" / Docker가 실행 중이 아님
Ensembler는 컨테이너 런타임이 실행 중이어야 합니다. **Docker Desktop**을 사용한다면
시작한 뒤 (설치만이 아니라) 실행 중이라고 표시될 때까지 기다리면 Ensembler가 계속
진행됩니다. 설치되어 있지 않다면 해당 화면의 다운로드 링크를 따르세요. **OrbStack**이나
**Podman** 같은 대안을 사용하나요? 그것도 괜찮습니다 — 실행 중인지, 그리고 `docker`와
`docker compose`가 작동하는지만 확인하세요.

## 서비스가 시작되지 않음
- 서비스의 **⋯ 메뉴 → 로그 보기**를 열어 무엇을 문제 삼는지 확인하세요.
- **⋯ 메뉴 → 다시 시작**을 시도하세요.
- 서비스가 시작을 마치는 동안 가져오기 알림과 라이브러리 스캔에 1분 정도 걸릴 수
  있으니, 첫 실행 후에는 잠시 기다려 주세요.

## Docker 메모리나 디스크 공간에 대한 경고
Ensembler는 Docker에 할당된 메모리가 적거나 미디어 디스크가 거의 가득 찼을 때
경고합니다 — 서비스가 오작동하는 가장 흔하면서도 눈에 띄지 않는 두 가지 원인입니다.
- **메모리:** 컨테이너 런타임 설정에서 늘리세요 (Docker Desktop → Settings →
  Resources); 서비스 몇 개에는 4 GB 이상이 좋은 기준입니다.
- **디스크:** 다운로드/미디어가 사용하는 드라이브의 공간을 확보하거나, **구성**
  화면에서 서비스를 더 큰 드라이브로 지정하세요.

## 서비스를 열 때 나타나는 "Not Secure" 경고
이제 서비스는 **Ensembler 안에서** 탭으로 열리므로 이 경고가 보이지 않아야 합니다.
서비스의 **⋯ 메뉴 → 브라우저에서 열기**를 사용하거나(또는 Ensembler를 웹
브라우저에서 실행할 때)만 나타납니다. 로컬 서비스는 `http://localhost`로 실행되며,
브라우저는 이를 "Not Secure"로 표시합니다 — 여러분 자신의 컴퓨터에 있는 서비스에는
당연하고 무해합니다. 데이터가 컴퓨터를 벗어나지 않습니다.

## 포트가 이미 사용 중임
Ensembler는 설정 중에 포트를 확인하고 기본 포트가 사용 중이면 자동으로 사용 가능한
포트를 선택하므로, 이 경우는 드뭅니다. 그래도 서비스가 바인딩되지 않으면 다른 앱이
포트를 차지했을 수 있습니다 — 그 앱을 중지하거나, 서비스의 **구성** 화면에서 포트를
변경하세요.

## 내 데이터는 어디에 있나요?
- **앱 구성**은 사용자별 숨김 폴더에 있습니다(*서비스 관리 → 설정이 저장되는 위치*
  참조). 편집할 필요는 없습니다.
- **미디어**는 설정 중에 선택한 위치에 그대로 있으며, Ensembler가 이동하거나
  삭제하지 않습니다.

## 무언가 심하게 멈춤 — 새로 시작
**설정 → 초기화 → 전체 초기화**는 모든 서비스와 그 설정을 중지 및 제거하고
Ensembler를 깨끗한 상태로 되돌립니다. **미디어 파일은 영향을 받지 않습니다** —
서비스와 그 구성만 제거됩니다. 이후에는 설정 마법사를 다시 거치게 됩니다.

## 여전히 해결되지 않나요?
서비스의 **로그 보기**와 **설정 → 고급 → 진단**에서 세부 정보를 가져오세요 — 문제를
보고할 때 포함하면 가장 유용한 것들입니다.
