# 疑难解答

## "Docker is required" / Docker 未运行
Ensembler 需要一个正在运行的容器运行时。如果你使用 **Docker Desktop**，
启动它并等到它报告正在运行（不仅仅是已安装），
Ensembler 便会继续。如果尚未安装，请按照那个屏幕上的下载链接操作。使用
诸如 **OrbStack** 或 **Podman** 这样的替代方案？那也没问题 ——
只要确保它正在运行，并且 `docker` 和 `docker compose` 能正常工作。

## 某个服务无法启动
- 打开该服务的 **⋯ 菜单 → View logs**，查看它在报什么错。
- 尝试 **⋯ 菜单 → Restart**。
- 导入通知和媒体库扫描在服务完成启动时可能需要一分钟，
  所以首次启动后请稍等片刻。

## 关于 Docker 内存或磁盘空间的警告
当 Docker 分配的内存很少，或媒体磁盘几乎已满时，Ensembler 会发出警告
—— 这是导致服务异常最常见、也最隐蔽的两个原因。
- **内存：** 在你的容器运行时设置中调高它（Docker Desktop →
  Settings → Resources）；对于几个服务来说，4 GB 或以上是一个不错的基准。
- **磁盘：** 在你的下载/媒体所用的驱动器上释放空间，或从服务的
  **Configure** 屏幕把服务指向一个更大的驱动器。

## 打开服务时出现 "Not Secure" 警告
服务现在**在 Ensembler 内部**以标签页打开，所以你应该不会看到这个警告。它
只会在你使用某个服务的 **⋯ 菜单 → Open in browser**（或在网页浏览器中运行
Ensembler）时出现。本地服务通过 `http://localhost` 运行，浏览器会
把它标记为 "Not Secure" —— 对于运行在你自己机器上的服务来说，这是意料之中且
无害的；你的数据并没有离开你的电脑。

## 某个端口已被占用
Ensembler 会在设置期间检查端口，并在默认端口被占用时自动选取
一个空闲端口，所以这种情况很少见。如果某个服务仍然无法绑定，可能是另一个应用
抢占了它的端口 —— 停止那个应用，或从该服务的
**Configure** 屏幕更改端口。

## 我的数据在哪里？
- **应用配置**存放在一个隐藏的、每用户独立的文件夹中（参见*管理你的
  服务 → 你的设置存放在哪里*）。你不需要去编辑它。
- **你的媒体**保留在你设置时选择的任意位置，Ensembler 绝不会移动或
  删除它。

## 有些东西严重卡住了 —— 从头开始
**Settings → Danger zone → Reset everything** 会停止并移除所有服务及
其设置，并让 Ensembler 恢复到干净的状态。**你的媒体文件
不受影响** —— 仅移除服务及其配置。之后你会
重新走一遍设置向导。

## 仍然卡住？
从某个服务的 **View logs** 以及仪表盘底部的 **Diagnostics**
面板中获取详细信息 —— 在报告问题时，那些是最有用的
可供附上的内容。
